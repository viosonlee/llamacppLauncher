# KVMem 硬件一键配置、倍数归一化与模型隔离

需求：REQ-127、REQ-128。这里的配置是**当前引擎、当前模型的未实测保守起点**，不是实测最优参数，也不是内置性能测试产品。

## 不懂参数时怎么用

在 KVMem 参数页使用「按硬件一键配置」：

1. 后台读取 CPU、RAM、GPU 和目标缓存盘信息，结合当前模型大小与架构准备一份静态保守策略；硬件探测有截止时间，未知数据明确标注，不阻塞 UI dispatcher。
2. 查看策略摘要与限制提示。策略不能保证模型一定能载入、整个进程 RAM 不超限或性能最优；探测与准备本身不启动模型、不改运行服务。
3. 应用时保存**后台准备好的同一份完整策略**，只作用于当前引擎的当前模型，下次启动生效。应用前重新核验引擎、规范化模型路径与模型签名，并通过参数快照 CAS（比较后提交）检查；模型已切换、文件已改变或参数被并发编辑时拒绝覆盖，需重新准备配置。

来源是 `KvmemHardwareConfigurationService` 的静态硬件策略；硬件探测和策略准备在后台任务中完成，应用时不重新计算另一份策略。不读取或写入实测推荐缓存，也不启动候选模型或执行多轮性能测试。

B/R、Host 配额、保留历史、预填充分块与搬运区等底层选项仍可按需手工调整。SSD 配额大于 0 时必须明确指定目录并检查目标盘余量；未知介质不能被宣称为 SSD/NVMe，磁盘容量也不代表磁盘速度。

## 静态硬件配置的依据与边界

- CPU 物理/逻辑核心用于选择保守线程起点，不通过负载测试寻找最快线程数。
- RAM 与 GPU 总容量用于识别硬件档位，当前可用内存、模型大小与目标盘余量用于提示资源约束；不把当前空闲显存当成硬件总容量。
- 当前接入范围仍是独立 `kvmem` 后端、`qwen35moe` GGUF、单 GPU、fp16/q8_0 与普通解码；不能给原版 llama.cpp、PolyStrata 或不支持的模型套用 KVMem 参数。
- B/R 等预算必须满足原生协议和跨字段关系；硬件配置不是提高所有预算的理由，不能盲目分配大额 Host KV 内存。
- 模型大小只能提供资源估计，不能精确代表运行期峰值。模型权重、专家驻留、计算工作区、Python/服务开销、驱动与其它进程都可能额外占用 RAM 或显存。

**KV 分层不等于模型权重分层。** KVMem 将 KV 缓存在 GPU、主机 RAM 与 SSD 之间管理；Host/SSD 配额针对 KV，不是模型权重的 RAM 预算，也不是整个进程或整机的内存上限。增加 SSD KV 配额并不会自动把模型权重移出 RAM，因此没有「整个进程 RAM 保证不超限」或「消除所有 OOM」的承诺。

## 输入不是倍数时

仅对明确声明 `MultipleOf` 的整数归一化。当前 KVMem B/R 必须 32 对齐：

| 输入 | 生效值 | 原因 |
|---:|---:|---|
| 8193 | 8192 | 最近的 32 倍数 |
| 8208 | 8192 | 等距离时取较小值 |
| 8210 | 8224 | 上面的 32 倍数更近 |
| R=511 | 512 | 最近合法值 |

输入过程中不跳数；**失焦、回车或保存**时调整，旁边展示原值/新值与原因并记录日志。越界整数取合法范围内最近的倍数；空值保留默认语义，非法文字、小数、NaN 等仍报错。

`B+R<=context`、`prefill<=R` 等跨字段关系仍检查，不偷偷修改其它参数。未声明倍数的字段不会被强行 32 对齐。GUI 与 native 组装共用 [ParameterNormalizer](../gui/LlamaManager/Engines/ParameterNormalizer.cs)；手工配置中的非对齐 B/R 在启动时也会记录有效调整，`BuildLaunch` 不修改传入配置。

## 按引擎、按模型自动保存，不串参数

- 非 llama.cpp 后端分别保存 `EngineSettings.ModelPresets`，键为规范化绝对模型路径；llama.cpp 继续保存自己的模型原始参数预设。
- 编辑只更新当前后端的当前模型。切换模型前保存当前编辑，切回已有模型时恢复它的完整预设，包括端口与用户手选路径。
- 新模型只继承必要的引擎安装公共路径，不继承上一模型的 context、threads、KV 预算、SSD 配额、KV 类型或监听设置；端口/host 使用该后端声明的默认值。
- 渲染参数页不改写运行设置；旧控件事件不能写入切换后的模型。一键应用也遵守同样的模型作用域，并额外核验准备时的模型签名与参数快照 CAS。
- 引擎更新仍可同步**引用同一旧公共安装路径**的预设；独立手工路径不迁移，模型参数不因更新而改变，运行会话身份不被参数保存覆盖。
